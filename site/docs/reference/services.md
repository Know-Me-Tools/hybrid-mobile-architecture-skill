# Services and integration boundaries

KnowMe Builder is primarily a generator and instruction package. It does not
silently start an application backend. This catalog distinguishes services the
Builder **depends on**, services it **integrates**, and services a selected
profile **generates or expects**.

## Authority services

### Universal Agent Runtime

**Role:** Sole authority for agent execution, provider routing, prompts, run
lifecycle, skills executed by the runtime, governed tools, and A2UI/AG-UI
events.

**Modes:**

- embedded library for mobile and local-only use;
- service facade for desktop, web, and hosted use; and
- deterministic implementation for tests.

**Why:** Multiple application-owned loops produce incompatible cancellation,
tool policy, persistence, and recovery behavior. One `UarRuntimeFacade` gives
every surface the same typed contract.

**Common uses:** start or resume a run, stream model output, request a governed
tool, persist run state, continue an A2UI action, and recover after restart.

**Boundary:** Raw MCP transport stays internal. Clients cannot choose trusted
roles, tenants, tool permissions, or bypass confirmations.

### Prometheus control plane

**Role:** Development workflow authority: canonical KBD state, pause, resume,
cancel, revise, audit, lease/fencing, and cross-harness handoff.

**Why:** Skills are portable instructions, not durable concurrency control.
Prometheus supplies the event journal and single-writer ownership needed when
work moves between machines or harnesses.

**Common uses:** claim a mutation lease, checkpoint before architectural review,
audit exact work position, revise a plan, and hand off to another harness.

**Boundary:** Builder hooks remain advisory. Compatibility waypoint/progress
files are read-only projections.

## Application boundary services

### Axum application/BFF gateway

**Role:** Authenticated server boundary between browser clients, application
services, and service-mode UAR.

It validates request size and schema, creates `VerifiedSession`, derives tenant
and actor, applies project policy, submits idempotent commands, propagates
cancellation, and streams events.

Use it in `governed-web-shell` and `axum-web`. Do not expose raw provider,
database, or tool transports directly to browsers.

### Verified identity and JWKS validation

**Role:** Create trusted server-side session context from signature, issuer,
audience, expiry, and revocation-aware validation.

`UntrustedTokenHints` may display non-sensitive hints but must never authorize.
Tenant IDs come from verified identity, not request bodies or client state.

Common providers include Ory Kratos, Supabase Auth, or another issuer that
meets the same verified-session contract. Project overlays own the exact role
model.

### Cedar or project policy engine

**Role:** Decide whether a verified actor may perform an application mutation,
agent trigger, tool effect, or release action.

Policy is evaluated outside prompts. Persona instructions and MCP annotations
cannot grant permissions. Projects may add named-human release gates for money,
documents, legal actions, or other externally consequential effects.

### Legacy application bridge

**Role:** Versioned postMessage-style boundary for an independently deployed or
frozen application embedded in a governed shell.

The bridge verifies origin, source window, protocol version, message type,
correlation, and capability. The host translates permitted intent into its BFF
or UAR calls; the embedded application never receives direct runtime access.

## Event and projection services

### AG-UI event stream

**Role:** Ordered runtime-to-client event transport.

Every event carries protocol version, stable event ID, run ID, sequence,
timestamp, type, typed payload, and optional causal parent. SSE supports resume
from the last committed event. Duplicate and unknown events remain
inspectable.

### A2UI surface projection

**Role:** Typed declarative UI emitted from governed runtime activity.

A2UI components render registered types and validated properties. Actions
return to UAR with run, event, and idempotency IDs. The renderer shows approval,
denial, cancellation, failure, and resumed states without becoming an executor.

### ContentBlock rendering contract

**Role:** Cross-platform rich output boundary for text, thinking, code,
citations, memories, tool use/results, skills, artifacts, images, and dividers.

Rust owns the canonical discriminated union. Dart and TypeScript mirrors are
generated and exhaustively rendered.

## Entity, persistence, and sync services

### Prometheus Entity Management

**Role:** Normalized entity graph and mutation surface for durable application
state.

React components consume feature hooks; Flutter widgets consume Riverpod
providers. Transport registration and local-store access stay below those
layers. PEM replaces request caches such as TanStack Query in this architecture.

### PGlite

**Role:** Browser-local relational projection and offline operation queue.

It provides fast local reads and restart recovery but is not trusted for
authorization. Remote mutations still pass through Axum and project policy.

### pglite-oxide

**Role:** Typed embedded PostgreSQL-compatible storage for the Tauri desktop
tier where selected.

Access is exposed through generated Tauri commands, not direct component calls.
Command registration, permissions, TypeScript bindings, and tests are generated
from one command manifest.

### SQLite and sqlite-vec

**Role:** Mobile relational and vector storage behind Rust/FFI repositories.

Flutter receives typed domain objects and events, not database handles. Vault
and other local-only data use physically and logically separate storage paths.

### Relational synchronization

**Role:** Scope-bound shared-data replication with a durable idempotent write
queue.

The server remains authoritative. Devices hold declared user subsets and
versioned lookup bundles, not a mirror of the database. Unknown privacy class
fails closed.

### Loro peer-profile vault

**Role:** Device-to-device CRDT synchronization for personal profile,
preferences, and agent-learned facts that must never persist on a server.

Paired device keys authenticate peers. Signaling is an untrusted pipe. Loss of
all devices loses the vault unless the user explicitly created an encrypted
export.

### Client retrieval service

**Role:** On-device embeddings and retrieval behind one `RagEngine` facade.

The fixed cross-tier dimension is 384. Web uses pgvector in PGlite, desktop uses
the selected local adapter, and mobile uses sqlite-vec. Vault retrieval remains
local-only and separate.

## Model services

### `InferenceProvider`

**Role:** Engine-neutral local generation interface.

Default engines are selected per device:

| Device | Engine |
|---|---|
| Android | LiteRT-LM |
| iOS | MLX-Swift |
| macOS | MLX-C |
| Other desktop | llama.cpp through `llama-cpp-2` |
| Web | WebLLM |

The execution lane—`cloud`, `local`, or `uar`—is selected per turn. Unknown
lanes are rejected instead of silently falling back.

### Model acquisition

**Role:** Revision-pinned, resumable, checksummed model delivery with RAM
preflight.

Partial files never use final paths. Native loads are budgeted before execution
because iOS may terminate an over-budget process without a catchable error.

## Development MCP services

### Dart and Flutter MCP

Used for Flutter analysis, device discovery, app launch, hot reload, widget
inspection, and the visual verification loop. The global installer adds it to
supported harness configurations when the `dart` command is available.

### shadcn MCP

Used to inspect and add supported shadcn components instead of recreating
primitives from memory. It assists presentation work but does not own design
tokens, architecture, or acceptance.

## Documentation service

### Docusaurus publication portal

The `site` package builds static public documentation with local search,
Mermaid, sanitization, link enforcement, responsive accessibility checks, and
GitHub Pages delivery.

It intentionally excludes authenticated application services, databases,
private wikis, raw sessions, credentials, and client data.
